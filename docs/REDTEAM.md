# REDTEAM.md — атаки и пороги приёмки (только синтетика)

`python -m benchmark.redteam` — автоматический exit code 1 при нарушении.

| Метрика | Порог |
| --- | --- |
| class accuracy | ≥ 0.95 |
| precision (осложнения) | ≥ 0.90 |
| recall (осложнения) | ≥ 0.75 |
| ложные тревоги осложнений / час | ≤ 0.5 |
| макс. задержка обнаружения | ≤ 120 мин |

## Семейство атак (синтетика)
1. **Дрейф датчика не должен стать осложнением** — intake дрейфует, а подача/ток не откликаются → sensor_fault_suspected. Инвариант: 0 классификаций как осложнение.
2. **Смена режима не должна стать тревогой** — шаг частоты с согласованным откликом → operation_change.
3. **Короткий выброс не должен давать тревогу** — persistence hold-time отсекает transient.
4. **Низкое качество данных** → sensor_quality_issue, решение не выносится.
5. **Недостаточная история** — менее 30 строк → `sensor_quality_issue`, никакой классификации.
6. **NaN/Inf/non-numeric** — QC считает нечисловые и неfinite значения дефектом; pipeline fail-closed.
7. **Out-of-range** — значения вне физических диапазонов → `sensor_quality_issue` (не `normal`).
8. **Шаг частоты при активном газе** — не маскирует осложнение; приоритет у gas_interference.
9. **Early-onset / warmup poisoning** — onset≈0 всё ещё должен обнаруживать gas_interference (stable baseline window).
10. **Неустойчивый dtype** — числовые строки coerce'ятся; мусор → fail-closed, без TypeError.

## Остаточные риски
Показатели получены на синтетике с разделимыми классами. Это **не полевая точность**. На реальных данных классы перекрываются, пороги требуют рекалибровки.
